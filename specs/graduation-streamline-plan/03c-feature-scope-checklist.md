# Spec 03C: 功能范围执行清单

## 目的

把当前代码层面的功能取舍整理成一份可执行清单，作为后续清理与瘦身的直接依据。

本清单基于 `Spec 03B` 的产品定位：

`Relax-Git 是一个以开源仓库为内容载体、以代码快照和行级讨论为核心互动方式的开发者代码社交平台。`

## 一、明确保留

以下功能属于平台核心，不应被误删：

1. 用户注册、登录、个人资料
2. 仓库导入、仓库管理、仓库详情
3. 社区 feed、仓库发布、仓库浏览
4. 仓库点赞、收藏、评论
5. 快照生成、快照浏览、文件树、文件内容
6. 行级评论、回复、评论解决
7. 通知系统
8. 个人中心
9. 好友关系
10. 私聊
11. 在线状态
12. 简洁实用的运营管理控制台

## 二、保留但降级

以下功能保留，但不再作为公开主卖点：

1. 专用仓库发现 AI 助手
2. 搜索能力
3. 热门标签、热门语言等统计能力
4. 部分健康检查、性能指标、工程性展示页面

要求：

1. 只服务于主链路
2. 不再独立抢占主导航和产品第一印象
3. AI 必须围绕仓库推荐、方向检索、仓库简介三类能力收敛

## 三、冻结或下线候选

以下功能优先进入冻结或下线名单：

1. 群聊创建
2. 聊天室式表达
3. 群成员邀请入口
4. 泛聊天型 AI 表达
5. 与主链路重复的聊天入口

## 四、第一批已执行

本轮已经完成的代码调整：

1. 群聊创建接口已冻结，返回明确提示
2. 私信详情页已移除邀请成员入口
3. 前端公开文案已从“聊天室”收敛为“消息中心 / 私信”
4. AI 助手文案已从泛聊天改为“仓库发现助手”
5. AI 快捷问题已切换为热门仓库推荐、按方向找仓库、仓库简介
6. `/messages` 已成为真实消息中心页面，`/chat`、`/chat/bot`、`/chatroom` 退为兼容跳转
7. 消息中心已支持通过 query 直接打开仓库助手
8. WebSocket 与好友申请服务中的“聊天室通知”表述已收敛为消息通知语义
9. 后端群聊创建、成员邀请、成员移除能力已统一冻结并返回明确提示
10. 群聊 DTO 提示文案已改为中性“会话”表述，减少误导
11. 群聊 DTO 已从有效开发面中移除，只保留实际仍在使用的私信 DTO
12. `ChatType` 与 Prisma Schema 已明确标注：`GROUP` 仅作历史兼容，不再作为当前版本主能力
13. 前端真实消息中心组件已统一命名为 `MessagesCenterPage`，进一步去除 `chatroom` 心智干扰
14. `/chat/[id]` 已退为兼容跳转层，真实私信线程入口统一为 `/messages?chat=...`
15. 前端消息中心组件目录已统一收口到 `components/messages/*`
16. 前端消息状态主链已统一为
    `messages-store`、`contacts-store`、`use-messages-socket`、`types/messages`
17. 后端 `chats` 模块当前明确保留兼容命名，不在本阶段做目录级重命名
18. 后端 AI 控制器、AI 服务、私信服务与 Prisma 代理注释已继续从“泛聊天”收口到“仓库助手 / 私信会话”表达

## 五、第二批待执行

建议下一轮继续处理：

1. 评估 `chatroom` 兼容路由保留周期，并在后续版本择机彻底下线
2. 继续清理后端与 WebSocket 中仍残留的实现级命名，但以注释、提示文案、错误信息收口为主，不进行高联动目录级重命名
3. 继续压缩运行时调试痕迹，只保留真正有运维价值的错误日志
4. 评估是否需要在数据迁移层进一步弱化 `GROUP` 语义
5. 评估是否需要在 UI 中进一步弱化旧的 `/chat/[id]` 路由感知
6. 决定是否对消息中心做更明显的“社交平台”视觉收口

当前补充状态：

1. API `artifacts` 与 `repositories` 控制器中的开发期追踪日志已做第二轮清理。
2. 前端仓库详情页、网络状态提示、认证与若干 store 的运行时噪音已收口。
3. `/chat/[id]` 已退为兼容跳转层，真实私信会话入口统一收口到 `/messages?chat=...`。
4. 前端消息中心公开文案已继续从“聊天”收口到“私信 / 消息 / 会话”表达。
5. 后端 `chats`
   模块已完成评估：当前阶段保留兼容命名，更适合继续做低风险语义收口，而不是重命名接口与模块。
6. 后端 AI 与私信相关提示/注释已完成一轮低风险语义收口，并通过 API 类型检查。
7. 当前方向保持不变：保留社交主链路，删除答辩无助的“开发中间态”痕迹。

## 验收标准

1. 功能取舍有清晰书面依据
2. 后续每一轮删改都能对照清单执行
3. 不会再把“代码社交核心”与“过重社交扩展”混为一谈
