# Spec 04: 简洁实用版运营与管理控制台

## 目标

新增一个“够用、清晰、答辩友好”的轻量控制台，体现开发者对平台的管理视角和全局掌控力。

## 设计原则

1. 不做重后台，不做通用 CMS。
2. 只做能服务答辩、演示和日常观察的功能。
3. 尽量复用现有数据库与 API 能力。
4. 界面简洁，信息实用，避免复杂权限和流程设计。

## 控制台定位

控制台不是另一个大系统，而是 Relax-Git 的开发者视角页面。

它用于回答三个问题：

1. 平台现在整体运行得怎么样？
2. 社区里的核心数据是什么状态？
3. 作为开发者，我能不能对这个系统进行基本运营管理？

## 建议最小功能范围

### 1. 概览页

展示最核心的统计卡片：

1. 用户总数
2. 仓库总数
3. 已发布仓库数
4. 评论总数
5. 快照总数
6. 最近活跃趋势或最近新增量

### 2. 仓库管理页

展示：

1. 仓库名称
2. 所有者
3. 可见性
4. 是否发布到社区
5. 创建时间
6. 快照或活跃状态摘要

支持：

1. 搜索
2. 简单筛选
3. 查看详情入口

### 3. 用户与内容页

展示：

1. 用户列表
2. 最近评论
3. 基础活跃度信息

不追求复杂审核流，只做基础查看与简单管理入口。

### 4. 系统状态页

展示：

1. API 健康状态
2. Worker 健康状态
3. PostgreSQL / Redis 基础连接状态
4. 最近失败任务数量或异常摘要

## 明确不做

1. 复杂 RBAC 后台。
2. 大量批量管理操作。
3. 复杂图表系统。
4. 完整日志平台。
5. 审核工单流转。

## 技术实现建议

1. 优先在现有 Web 中增加管理员入口，而不是新开一个独立前端。
2. 后端新增聚合接口，而不是让前端拼接太多散接口。
3. 控制台先服务“查看与判断”，再考虑“修改与操作”。

## 答辩价值

这个模块的价值不在功能复杂，而在于它能证明：

1. 项目不是只有普通用户前台。
2. 开发者具备平台化管理视角。
3. 系统已经形成“用户端 + 管理端 + 服务端”的完整闭环。

## 验收标准

1. 控制台可以稳定访问。
2. 至少包含概览、仓库管理、系统状态三类信息。
3. 数据来自真实业务数据，而不是写死演示。
4. 视觉和交互足够清楚，不增加不必要复杂度。
