## 2. 已完成功能及实现方法

### 2.1 AI 智能对话功能

**功能说明**：用户可以和 AI 机器人聊天，询问电影推荐。AI 会记住之前聊过的内容，能够进行连贯的多轮对话。

**实现方法**：

1. **AI 引擎接入**
   - 使用智谱 AI（清华大学开发的中文 AI）提供对话能力
   - 每次用户发送消息，系统会把问题发送到智谱 AI 服务器
   - AI 分析后返回推荐内容，系统再展示给用户

2. **对话记忆功能**
   - 系统会自动保存最近 10 轮对话内容
   - 每次提问时，把之前的对话一起发给 AI
   - AI 就能理解"这部电影"、"刚才那个"等指代词

3. **打字动画效果**
   - 用户发送消息后，会显示"AI 正在输入..."的动画
   - 由三个小圆点不断跳动，表示 AI 正在思考
   - 收到 AI 回复后，动画消失，显示内容

4. **错误处理机制**
   - 如果 AI 服务器出错，系统会显示友好的错误提示
   - 不会让页面卡死或崩溃，用户可以继续使用

### 2.2 用户注册与登录系统

**功能说明**：用户可以注册账号、登录系统、上传头像，系统会记住登录状态。

**实现方法**：

1. **注册流程**
   - 用户输入用户名和密码
   - 系统检查用户名是否已被占用
   - 密码会被加密存储（使用 bcrypt 加密算法，无法被破解）
   - 注册成功后自动登录

2. **登录验证**
   - 用户输入用户名和密码
   - 系统从数据库查找用户信息
   - 验证密码是否正确（对比加密后的密码）
   - 登录成功后生成一个令牌（Token），像身份证一样证明用户身份

3. **令牌认证机制（JWT）**
   - 登录成功后，系统给用户一个特殊的字符串（Token）
   - 用户每次访问页面时，自动携带这个 Token
   - 服务器验证 Token 有效性，确认用户身份
   - Token 有效期 7 天，过期需要重新登录

4. **头像上传**
   - 用户选择图片文件（支持 PNG、JPEG、WEBP 格式）
   - 系统上传到云存储服务（Cloudinary）
   - 返回图片网址，保存到数据库
   - 下次打开页面时，从网址加载头像

5. **在线状态显示**
   - 用户登录后，数据库记录为"在线"
   - 好友可以看到用户头像旁边的绿色小圆点
   - 用户关闭页面后，状态变为"离线"

### 2.3 实时聊天室功能

**功能说明**：用户可以添加好友、发送消息、查看聊天记录，消息会实时送达对方。

**实现方法**：

1. **好友系统**

   **添加好友流程**：
   - 用户在搜索框输入用户名
   - 系统从数据库查找匹配的用户
   - 点击"添加好友"按钮，发送好友申请
   - 对方收到通知，可以同意或拒绝
   - 同意后，双方建立好友关系，自动创建聊天窗口

   **智能申请处理**：
   - 如果 A 向 B 发送申请，B 也向 A 发送申请
   - 系统会自动检测到双向申请，直接通过
   - 避免重复申请和等待时间

2. **实时消息推送（WebSocket 技术）**

   **传统方式的问题**：
   - 普通网页需要刷新才能看到新消息
   - 就像发短信，必须主动查看才知道有新消息

   **WebSocket 解决方案**：
   - 浏览器和服务器建立一个持久连接
   - 连接会一直保持，不会断开
   - 服务器有新消息时，主动推送给浏览器
   - 用户立即看到新消息，不需要刷新

   **具体实现过程**：
   - 用户 A 发送消息："晚上一起看电影吧"
   - 消息先保存到数据库
   - 服务器通过 WebSocket 推送给用户 B
   - 用户 B 的聊天窗口立即显示新消息
   - 整个过程不到 200 毫秒（0.2 秒）

3. **未读消息统计**
   - 每个聊天窗口记录用户最后阅读时间
   - 对比消息发送时间和阅读时间
   - 计算出未读消息数量
   - 在好友列表显示红色数字角标
   - 用户打开聊天后，自动标记为已读

4. **消息历史记录**
   - 所有消息都保存在数据库中
   - 用户打开聊天时，先加载最近 50 条消息
   - 向上滚动时，自动加载更早的消息
   - 采用分页加载，避免一次加载太多卡顿

5. **单边删除消息**
   - 传统删除：消息从数据库彻底删除，双方都看不到
   - 单边删除：只是标记"对这个用户不可见"
   - 实现方法：数据库有个 MessageVisibility 表
   - 记录每条消息对每个用户是否可见
   - 用户 A 删除后，A 看不到，但 B 仍能看到

## 5. AI 对话系统详解

### 5.1 后端实现 - AI Service

**文件位置**: `apps/api/src/ai/ai.service.ts`

#### 核心代码解析

```typescript
import OpenAI from 'openai';

@Injectable()
export class AiService {
  private client: OpenAI;

  constructor(private configService: ConfigService) {
    // 初始化智谱 AI 客户端
    this.client = new OpenAI({
      apiKey: process.env.ZHIPU_API_KEY,
      baseURL: 'https://open.bigmodel.cn/api/paas/v4/',
    });
  }

  async chat(message: string, history: Array<{ role: string; content: string }>) {
    // 1. 构建对话上下文
    const messages = [
      {
        role: 'system',
        content: '你是一个专业的电影推荐助手，可以根据用户喜好推荐电影...',
      },
      ...history, // 历史对话（最近10轮）
      {
        role: 'user',
        content: message, // 用户当前问题
      },
    ];

    // 2. 调用智谱 AI API
    const response = await this.client.chat.completions.create({
      model: 'glm-4-flash', // 使用 GLM-4 快速模型
      messages: messages,
      temperature: 0.6, // 控制回复创造性（0-1）
      max_tokens: 300, // 限制回复长度
      top_p: 0.8, // 控制回复多样性
    });

    // 3. 返回 AI 回复
    return response.choices[0]?.message?.content;
  }
}
```

#### 技术原理解释

**什么是智谱 AI？**

- 智谱 AI 是清华大学开发的中文大语言模型
- 类似 ChatGPT，但更懂中文和中国文化
- 可以理解自然语言，进行智能对话

**如何调用 AI？**

1. **准备对话内容**：包括系统提示词、历史对话、用户问题
2. **发送请求**：通过 HTTP 请求发送到智谱 AI 服务器
3. **接收回复**：AI 分析后返回生成的文本
4. **展示给用户**：将回复显示在聊天界面

**关键参数说明：**

- `temperature (0.6)`: 控制 AI 回复的"创造性"，越高越随机
- `max_tokens (300)`: 限制 AI 回复的最大字数（约 150-200 字）
- `top_p (0.8)`: 控制词汇选择范围，影响回复多样性

### 5.3 对话上下文管理

**为什么需要上下文？**

AI 需要"记住"之前说过的话，才能进行连贯对话。

**示例对话：**

```
用户：推荐一部科幻电影
AI：推荐《星际穿越》，这是一部经典的硬科幻电影...

用户：这部电影的导演是谁？【AI 需要知道"这部电影"指的是《星际穿越》】
AI：《星际穿越》的导演是克里斯托弗·诺兰...
```

**实现方式：**

```typescript
// 只保留最近 10 轮对话
const conversationHistory = messages
  .slice(-10) // 取最后 10 条消息
  .map(msg => ({
    role: msg.sender === 'user' ? 'user' : 'assistant',
    content: msg.content,
  }));
```

**为什么是 10 轮？**

- 太少：AI 记不住前面的对话
- 太多：消耗 token 过多，响应变慢
- 10 轮：平衡记忆和性能

## 6. 实时聊天功能

### 6.1 WebSocket 实时通信

**为什么使用 WebSocket？**

传统 HTTP 请求是"一问一答"模式，无法实时推送消息。WebSocket 建立了浏览器与服务器之间的"永久连接"，服务器可以主动推送消息给客户端。

**技术原理：**

```
传统 HTTP：
客户端 → 请求 → 服务器
客户端 ← 响应 ← 服务器
(每次通信都要重新建立连接)

WebSocket：
客户端 ⇄ 双向通道 ⇄ 服务器
(连接一直保持，双方可随时发消息)
```

### 6.2 聊天室架构

```typescript
// 后端 WebSocket 网关
@WebSocketGateway({ path: '/socket.io' })
export class WebSocketGateway {
  // 用户加入聊天室
  @SubscribeMessage('join:chat')
  async handleJoinChat(client: Socket, data: { chatId: string }) {
    await client.join(`chat:${data.chatId}`); // 加入房间
    console.log(`用户加入聊天室: ${data.chatId}`);
  }

  // 推送新消息给聊天室内所有人
  emitChatMessageNew(chatId: string, message: any) {
    this.server
      .to(`chat:${chatId}`) // 指定房间
      .emit('chat:message:new', message); // 广播消息
  }
}
```

**房间（Room）概念：**

- 每个聊天会话是一个"房间"
- 用户进入聊天时"加入房间"
- 发送消息时，服务器向"房间内所有人"推送
- 离开聊天时"离开房间"

### 6.3 前端消息同步

```typescript
// 监听 WebSocket 事件
useEffect(() => {
  if (!isConnected) return;

  // 监听新消息事件
  const unsubscribe = on('chat:message:new', message => {
    // 判断是否是自己发送的
    const isSelf = user.id === message.senderId;

    // 更新消息列表
    updateMessages(message);

    // 如果不是自己发的，增加未读数
    if (!isSelf) {
      incrementUnreadCount(message.chatId);
    }
  });

  return () => unsubscribe(); // 组件卸载时移除监听
}, [isConnected]);
```

## 8. 技术难点与解决方案

### 8.1 AI 对话连贯性

**问题：** AI 回复缺乏上下文，无法进行多轮对话

**解决方案：**

```typescript
// 方案 1: 客户端存储对话历史
localStorage.setItem('ai-chat-history', JSON.stringify(messages));

// 方案 2: 每次请求携带最近 10 轮对话
const history = messages.slice(-10).map(msg => ({
  role: msg.sender === 'user' ? 'user' : 'assistant',
  content: msg.content,
}));
```

### 8.2 实时消息去重

**问题：** WebSocket 推送和 HTTP 响应可能导致消息重复显示

**解决方案：**

```typescript
// 消息去重函数
const deduplicateMessages = (messages: ChatMessage[]) => {
  const seen = new Set<string>();
  return messages.filter(msg => {
    if (seen.has(msg.id)) return false; // 已存在，过滤掉
    seen.add(msg.id);
    return true;
  });
};
```

### 8.3 AI API 错误处理

**问题：** AI 服务可能因余额不足、限流等原因失败

**解决方案：**

```typescript
try {
  const reply = await aiService.chat(message, history);
  return reply;
} catch (error) {
  // 错误分类处理
  if (error.status === 402) {
    return '抱歉，AI 服务余额不足...';
  }
  if (error.status === 429) {
    return '抱歉，请求过于频繁...';
  }
  return '抱歉，处理出现错误，请稍后重试';
}
```

### 8.4 用户隔离存储

**问题：** 多用户共用一台电脑时，AI 对话历史混淆

**解决方案：**

```typescript
// 按用户 ID 隔离存储
const userAiChatKey = `ai-chat-history-${user.id}`;
localStorage.setItem(userAiChatKey, JSON.stringify(messages));

// 登录时清理旧用户数据
const oldGlobalRecord = localStorage.getItem('ai-chat-history');
if (oldGlobalRecord) {
  localStorage.removeItem('ai-chat-history'); // 清理全局记录
}
```
